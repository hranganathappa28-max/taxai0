# TAXAI Production Rollout Roadmap — 6 Weeks, 5 Interns

**Author:** Staff Engineer · **Status:** Binding · **Audience:** Interns A–E + reviewers
**Goal:** Take TAXAI from a 26,153-LOC single-file, localStorage-only, no-auth React app to a multi-tenant SaaS that Lithuanian accounting firms can safely use — auth, tenant isolation, tamper-evident audit, GDPR/BDAR rights, resilient backend, CI/CD, observability, and an honest go/no-go gate.

> **Read this first — scope honesty.** The grounding survey, the original track designs, and the adversarial critique all agree on one thing: *the full vision is a multi-quarter senior-team effort, not 30 intern-weeks.* This roadmap does **not** pretend otherwise. It defines a **6-week MVP-to-production-pilot** that is genuinely safe for a **small, contractually-onboarded set of design-partner firms** — not an open self-serve launch. Everything that cannot credibly be intern-built in 6 weeks (qualified eIDAS TSA, external pen test, signed DPAs, legal counsel sign-off, production hosting/IaC, billing) is **explicitly assigned, scoped, and gated below** — most as *"contracted/procured, integration-ready"* rather than *"fully delivered."* A green Week 6 means **"safe for supervised pilot with named firms under signed paper,"** not *"open the doors."* Anyone who reports green without that distinction has failed the bar.

## 1. Engineering bar — non-negotiable operating standards

These apply to **every** intern, **every** PR, **every** week. They are not aspirational; they are the floor. Falling below any of them blocks merge.

| Standard | Rule |
|---|---|
| **No merge without review** | Every change needs ≥1 approving review from a **CODEOWNER** for the touched area. No self-merge. No "I'll review after." |
| **CI is the gate, not the human** | `npm test` (≥227 tests, 0 failures) **and** `npm run build` green on every PR. Local Builder/Checker loop (`/buildloop`) must be green **before** you open the PR — CI re-runs it as the source of truth. |
| **Tests ship with code** | A behavior change with no test is incomplete. Tax-critical math (VAT position, FR0600 boxes, risk score, hash-chain) **must** have deterministic tests. **Never** weaken, skip, `.only`, or delete a test to go green — fix the code (per `CLAUDE.md`). |
| **Coverage ratchets, never erodes** | Thresholds only go **up**. CI hard-fails any per-metric or per-file coverage regression. Lowering a threshold requires a written, reviewer-approved exception in the PR. |
| **Gates are objective** | A gate is a passing automated test, a tool score (TLS A, 0 high/crit SAST), a signed document, or a **recorded, reproducible** demo with a scripted assertion. **A pasted curl transcript or a screenshot is NOT a gate.** If it can't be re-run in CI or re-demoed on demand, it doesn't count. |
| **Demos are pass/fail** | Each Friday, every intern demos that week's gates **live or via a committed test/CI run**. The outcome is recorded "pass" or "fail" per gate. Partial credit is "fail." |
| **No silent failure** | Catch-and-`console.log` is a defect. Every error path either surfaces to the user, increments a metric, or writes an audit row — or it gets a ticket. |
| **Definition-of-Done discipline** | A track's weekly goal is done when **all** its acceptance gates are green **and** it has not broken any other track's gate. "A fix that breaks a previously passing check" stops the line (per `CLAUDE.md` loop rules). |
| **Reviewer pool is named** | See §1.1. "A domain reviewer" with no name is not a process. |

### 1.1 Review capacity (resolves critique: "no defined pool of reviewers")

One staff engineer cannot be the sole acceptance authority for ~30 weekly gates across 5 parallel tracks — that degrades to rubber-stamping. So:

- **Cross-review is mandatory and assigned.** Interns review each other's PRs on a fixed matrix: **A⇄E** (identity/platform), **B⇄D** (security/CI), **C⇄A** (compliance/identity). Every PR gets one peer reviewer (matrix) **plus** the CODEOWNER.
- **Staff engineer reviews only the load-bearing gates**, not every PR: the **Week-1 Foundation exit**, each track's **Week-3 mid-point**, and the **Week-6 rollout sign-off**. Routine weekly gates are signed by the **assigned peer reviewer**, recorded in the PR.
- **Tax-engine changes** (the `TaxAI.jsx` engine regions: `computeFr0600`, `computeRiskScore`, `runAllRules`, `reconcileISAF`, payroll/VAT-2026, hash-chain) route via CODEOWNERS to the **staff engineer** — non-negotiable, because a wrong number here is a wrong tax filing.
- **External sign-offs that interns cannot self-attest** (legal regime mapping, pen test, DPA execution) are **procured/scheduled by the staff engineer in Week 1** and tracked as rollout blockers (§6), not faked internally.

## 3. Week-1 Shared Foundation Sprint

The whole team builds the skeleton together **before** splitting. This directly answers the critique's **FATAL ordering inversion**: the survey says *"DB+API → auth → tenancy → observability → compliance."* We honor that ordering **inside Week 1** by making the backend the critical path and gating everyone else's split-out on it — but we compress only the *skeleton*, not the *features*, into the joint week.

### 3.1 Sequencing rule (breaks the dependency cycle)

The dependency graph A↔B↔C↔E is a **cycle**, not a DAG. We cut it with a **stub seam** and a **critical-path owner**:

- **Intern E is the designated critical-path owner.** If E's skeleton slips, the whole team's split-out slips, and E gets pulled help from A and D before anything else proceeds. This is explicit, not implicit.
- **The tenant/auth seam is a stubbed interface from Day 1.** E ships `verify(req)` behind `FEATURE_AUTH=false` that reads `x-tenant-id`. A, C, and E all code against **that interface contract**, not against each other's running code. A drops real JWT verification into the same seam in Week 2; nothing upstream has to be rewritten. This kills the "C needs A's JWT in Week 1" impossibility — **C's Week-1 audit write uses the stub identity, and the `actor_user_id` source is swapped to the verified JWT in Week 2 with no schema change** (the column and write-path are identical; only the source of the value changes).
- **RLS context is designed into the persistence layer from Week 1**, even while the verifier is stubbed: every tenant query runs inside a transaction that does `SET LOCAL app.org_id = $fromSeam`. This avoids the critique's "retrofit RLS context into already-written paths" rework — the wrapper exists before the real verifier does; Week 3 only tightens the policy and the value's provenance.

### 3.3 Foundation **exit gate** (all must pass; staff-engineer signed)

1. **Live 2-browser persistence:** seed a twin in browser 1 → persists to Postgres as N hash-chained events; clear localStorage, load in browser 2 → twin restores. *Acceptance is **semantic equality of the restored event log + verified hash chain**, not byte-identical JSON* (resolves "byte-identical is fragile/gameable" — we assert `eventCount` equal **and** `verifyEventChain` passes **and** every event's `(type,payload,seq,hash)` matches, which is the real guarantee).
2. **Server hash == client hash:** same events fed to in-browser `createEventStore()` and the server path produce identical final hash; a mutated event is **rejected** server-side (parity with `loadAppend` 15435). Automated test.
3. **Append-only proven:** SQL `UPDATE`/`DELETE` on `twin_events` raises the trigger error; out-of-order `seq` → 409. Automated test.
4. **No proxy regression:** `/api/ai` returns identical output to old server for a recorded fixture; all **227 tests green**; `npm run build` green.
5. **CI bites:** a deliberately failing-test PR is **blocked** from merge by `ci.yml` (shown as a CI run, not a screenshot); a green PR merges. CI wall-time < 8 min.
6. **Coverage baseline is real (not a non-gate):** `coverage-summary.json` is committed **and** Week-2 thresholds are **pre-registered in `vitest.config.js` as `>= baseline`** this week (so Week 1 ships an enforceable floor, not "≥0% passes").
7. **Seam contract published:** `docs/PLATFORM.md` documents the `verify(req)` interface; A/C/D have committed code that imports it.
8. **External blockers opened:** counsel engagement (regime mapping), pen-test vendor RFQ, and DPA/sub-processor list are **tracked tickets owned by the staff engineer** — visible, not assumed.

> **If the Foundation exit gate is not fully green by end of Week 1, the team does not split.** A, B, C, D pause feature work and pair onto E's blockers. This is the single most important schedule rule.
